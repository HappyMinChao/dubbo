# Dubbo3 路由规则全景对比表

## 📊 核心对比

| 路由规则 | 应用场景 | 匹配维度 | 配置复杂度 | 容错能力 | 性能影响 | 优先级 |
|---------|---------|---------|----------|--------|--------|-------|
| **亲和路由** | 同机房调用、跨域容灾 | 单维度（如region） | ⭐ 简单 | ⭐⭐⭐⭐⭐ 很强(ratio降级) | 低 | P2 |
| **标签路由** | 灰度发布、多租户隔离 | 多维度标签 | ⭐⭐⭐ 中等 | ⭐⭐⭐ 中等(force强制) | 中 | P3 |
| **条件路由** | 流量分发、版本控制 | 多维度条件表达式 | ⭐⭐⭐⭐ 复杂 | ⭐⭐ 弱(返回空表示失败) | 中 | P4 |
| **规则覆盖** | 故障隔离、动态禁用 | 地址级 | ⭐⭐ 简单 | ⭐⭐⭐⭐ 强(支持强制) | 低 | P1 |
| **脚本路由** | 自定义复杂逻辑 | 任意JavaScript | ⭐⭐⭐⭐⭐ 很复杂 | ⭐ 弱 | 高 | P5 |
| **网格路由** | 服务网格、高级治理 | VirtualService + subset | ⭐⭐⭐⭐ 复杂 | ⭐⭐⭐ 中等 | 中 | P6 |

## 📝 详细特性对比

### 1. 匹配方式

| 路由规则 | 匹配方式 | 示例 |
|---------|--------|------|
| 亲和路由 | 自动匹配URL属性 | 消费者和提供者的 region 属性相同 |
| 标签路由 | 显式标签传递 | 通过 Invocation attachment 传递 tag 值 |
| 条件路由 | When-Then 表达式 | `method=sayHello => region=hangzhou` |
| 规则覆盖 | 地址黑名单/白名单 | `region=failover =>` （黑名单屏蔽） |
| 脚本路由 | JavaScript 自定义逻辑 | 脚本中编写任意过滤规则 |
| 网格路由 | VirtualService + DestinationRule | Istio 风格的服务网格规则 |

### 2. 容错机制

| 路由规则 | 无匹配时行为 | 容错特点 |
|---------|-----------|--------|
| 亲和路由 | 当亲和结果 < ratio% 时自动降级到全量 | **自动软降级** - 最好的容错 |
| 标签路由 | 无匹配标签返回无标签提供者（或返回空） | 支持 force 参数控制 |
| 条件路由 | 返回空列表或全量（取决于force） | 被动式容错 |
| 规则覆盖 | 直接禁用目标（无降级） | 强制执行，无容错 |
| 脚本路由 | 脚本异常返回全量 | 异常容错，但调试困难 |
| 网格路由 | 返回原始提供者列表 | 保护机制 - 防止过滤过度 |

### 3. 配置位置

| 路由规则 | 配置位置 | 作用范围 |
|---------|--------|--------|
| 亲和路由 | 配置中心：`{serviceName}.affinity-router` | 服务级/应用级 |
| 标签路由 | 配置中心：`{appName}.tag-router` | 应用级 |
| 条件路由 | 配置中心：`{serviceName}.condition-router` | 服务级 |
| 规则覆盖 | 配置中心：优先级设置为 1 | 全局最高优先级 |
| 脚本路由 | 配置中心：`{serviceName}.script-router` | 服务级 |
| 网格路由 | 配置中心/K8s：VirtualService 和 DestinationRule | 服务网格级 |

### 4. 适用场景详细分类

#### 亲和路由

✅ **最适合**
- 同机房调用：优先调用同机房提供者
- 跨域容灾：IDC 间的流量隔离
- 机房故障恢复：自动降级和升级

⚠️ **不适合**
- 需要复杂条件匹配
- 需要人工控制灰度发布
- 单维度属性以外的场景

#### 标签路由

✅ **最适合**
- 灰度发布：特定标签用户访问灰度版本
- 多租户隔离：不同租户标签对应不同提供者
- 业务隔离：特殊业务流量隔离处理

⚠️ **不适合**
- 动态变化的条件
- 复杂的逻辑运算

#### 条件路由

✅ **最适合**
- 流量分发：基于方法名、参数、版本分发
- 版本控制：特定版本请求路由
- A/B 测试：根据用户属性分流
- 黑名单管理：屏蔽特定条件请求

⚠️ **不适合**
- 高并发场景下的复杂表达式
- 需要频繁动态修改条件

#### 规则覆盖

✅ **最适合**
- 故障隔离：快速隔离故障提供者
- 动态禁用：紧急禁用某个提供者
- 灾难恢复：故障机房快速切流

⚠️ **不适合**
- 长期流量分发策略
- 需要灰度的场景

#### 脚本路由

✅ **最适合**
- 自定义复杂逻辑：内置路由无法满足
- 动态计算：实时计算路由目标
- 特殊算法：自定义分流算法

⚠️ **不适合**
- 性能敏感场景（脚本执行开销大）
- 容错要求高的场景
- 无法调试和维护

#### 网格路由

✅ **最适合**
- 服务网格集成：与 Istio/Envoy 配合
- 高级流量管理：金丝雀部署、蓝绿发布
- 故障注入：混沌工程测试

⚠️ **不适合**
- 非服务网格环境
- 简单的路由需求

## 🔄 优先级执行链

```
优先级从高到低：

P1 规则覆盖（最高）- 命中直接返回，无降级
  ↓
P2 亲和路由 - 自动 + 软降级
  ↓
P3 标签路由 - 显式传递标签
  ↓
P4 条件路由 - When-Then 表达式
  ↓
P5 脚本路由 - JavaScript 自定义
  ↓
P6 网格路由（最低） - VirtualService + subset
  ↓
负载均衡（默认轮询）
```

**执行流程**
- 高优先级规则命中时，直接返回结果，不继续后续规则
- 当 `shouldFailFast=true` 时，若某规则返回空列表，不继续后续规则
- 每个规则可独立启用/禁用

## 📈 性能指标

| 路由规则 | CPU占用 | 内存占用 | 延迟增加 | 缓存支持 | 吞吐量影响 |
|--------|--------|--------|--------|---------|----------|
| 亲和路由 | 很低(<1%) | 很低(<1MB) | <1ms | ✅ 支持 | 无影响 |
| 标签路由 | 低(1-2%) | 低(5MB) | <1ms | ✅ 支持 | 无影响 |
| 条件路由 | 中等(3-5%) | 中等(10MB) | 1-3ms | ⚠️ runtime=false | 1-2% 下降 |
| 规则覆盖 | 低(1-2%) | 低(5MB) | <1ms | ✅ 支持 | 无影响 |
| 脚本路由 | 高(5-10%) | 中等(10-20MB) | 5-10ms | ❌ 每次编译 | 5-10% 下降 |
| 网格路由 | 中等(2-4%) | 中等(10-15MB) | 2-5ms | ✅ MeshRuleCache | 2-3% 下降 |

## 选择建议矩阵

```
需求特征        最佳选择      备选方案       避免使用
─────────────────────────────────────────────────
简单场景         亲和路由      条件路由       脚本、网格
复杂条件         条件路由      网格路由       亲和路由
高可用           亲和路由      标签路由       脚本路由
灰度发布         标签+条件      网格路由       规则覆盖
故障隔离         规则覆盖      条件路由       亲和路由
服务网格         网格路由      条件路由       脚本路由
自定义逻辑       脚本路由      条件路由       亲和、标签
性能优先         亲和路由      规则覆盖       脚本路由
易维护性         亲和、标签    条件路由       脚本路由
```
